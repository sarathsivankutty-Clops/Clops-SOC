AiSOC · System overview

From security events to analyst decisions.

AiSOC is a security operations platform that accepts events from security tools, normalizes and correlates them, then gives analysts a place to review alerts and AI-assisted triage.

Event-driven processing OCSF-normalized ingestion Human-governed response

The event journey

Each component has a focused role in moving an event from its source to an analyst-ready alert.

01

Collect

Connectors poll external systems, or integrations push events to the Go ingest API.

02

Normalize

Ingest authenticates the request and maps vendor data into an OCSF-shaped event.

03

Detect & correlate

Kafka carries events to fusion, which evaluates detections and promotes findings to alerts.

04

Triage

Agents investigate fused alerts using a routed model, with deterministic triage as fallback.

05

Review

The web console presents alerts and investigation context for security analysts.

Collection & event processing

These services accept, transport, interpret, and enrich security data.

SRC

Log sources

SIEM, EDR, cloud, and application systems provide the security telemetry AiSOC processes.

The adjacent Security-Log-Generator can send synthetic sample events; it is not an AiSOC container.

CON

Connectors

Scheduled integrations fetch data from supported vendor APIs and submit event batches to ingest.

They are an integration path, not the event broker or the detection engine.

IN

Go ingest API

Provides authenticated HTTP ingestion endpoints, including POST /v1/ingest/batch. It validates credentials and tenant scope before accepting events.

OCSF

Normalizer

Applies connector-specific mappings and shapes incoming records into OCSF-compatible events with standard fields and source details.

K

Kafka

The event transport backbone. It carries normalized raw events to fusion and fused alerts to downstream consumers such as agents.

It queues and distributes events; Redis serves a different cache/runtime-state role.

F

Fusion & detection

Consumes events, applies detection and correlation logic, promotes eligible findings, persists alerts, and publishes fused alerts for triage.

AI-assisted analysis

Models support triage, while routing and fallback behavior keep the workflow explicit.

AG

Agents

Consume fused alerts and run the auto-triage pipeline. Agents can use threat context and record investigation results.

Auto-triage is read-only; it does not dispatch response actions by itself.

LLM

LiteLLM gateway

Routes AiSOC's logical task aliases to the model provider configured for the deployment. It provides a common model API boundary.

AI

Model & fallback

Ollama can provide local inference; deployments can instead configure a host or hosted provider. If model triage is unavailable, agents can use deterministic triage.

The model name depends on configuration. The checked-in default is Llama 3.2; a host-Ollama setup may select a different installed model.

TI

Threat intelligence

Fetches threat-intelligence data such as the CISA KEV feed and exposes it to the application. Related indicator and actor vectors can be stored in Qdrant.

MITRE

MITRE ATT&CK context

Technique metadata supports event normalization and agent context. Optional retrieval-augmented context uses embeddings when configured.

ACT

Governed actions

A separate service handles governed response-action workflows, keeping approval and action execution distinct from model-generated triage.

HITL

Analyst oversight stays in the loop

AI triage helps prioritize and explain findings. Response actions follow a separate governed path; review and operational decisions remain with the organization and its configured workflow.

Data stores: different jobs, one platform

AiSOC uses purpose-specific persistence rather than treating every store as interchangeable.

PG

PostgreSQL

Relational application records, promoted alerts, investigation data, and audit-related records.

RD

Redis

Cache and runtime state used by services. It is not the primary event queue.

Q

Qdrant

Vector storage for threat-intelligence context and configured semantic-memory or ATT&CK retrieval features.

CH

ClickHouse Full profile

Optional event-lake storage for analytical queries over archived events.

OS

OpenSearch Full profile

Optional full-text search for indicators of compromise.

N

Neo4j Full profile

Optional entity graph that supports relationships and contextual queries.

Application & analyst experience

The services that expose the system to analysts and operational integrations.

WEB

Web console

Analyst-facing interface. It proxies API, agent, and realtime routes so the browser can use the console's origin.

API

REST API

Serves application data and API operations used by the console and other clients, and connects to internal AiSOC services.

RT

Realtime gateway

Provides realtime communication, including WebSocket routes proxied through the web console.

Deployment profiles

Compose profiles determine which optional capabilities are started.

Core

The default services for ingestion, event transport, fusion, triage, API, and console, plus their configured model and data services.

Full

Adds optional data and analysis services, including the ClickHouse event lake, Neo4j entity graph, OpenSearch, enrichment, and UEBA.

Deployment specifics—such as host ports, model names, enabled profiles, and optional integrations—depend on Compose files and environment configuration. This page is a conceptual guide, not a live service-status view.
